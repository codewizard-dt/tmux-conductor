## [2026-09-19] research | Why a project-scoped task dispatch doesn't submit

Root cause: `host-server/state.ts::sendTextToPane` sends literal text then `Enter` via two synchronous `spawnSync` calls with zero delay, unlike `scripts/dispatch.sh`'s `sleep 0.3` ("let the UI render before submitting"); `dispatchTaskToAgent`'s `clearFirst` option (set only for project-scoped tasks) chains two such sends back-to-back, doubling the exposure and exactly reproducing the screenshot. Corroborated live via `logs/dispatch.jsonl`, which also surfaced a second, already-tracked compounding bug (BUG-0001/TASK-133: a second task dispatched into the same agent while its first `/tackle` dispatch's background sub-agents were still running). Wrote `raw/research/dispatch-clear-first-enter-race/` (index.md + sources.md, 8 sources). Recommends filing a new bug for the render-delay gap (separate from BUG-0001) and adding a 300ms settle delay before `Enter`, matching `sendDirectInput`'s own existing multiline-case precedent.
