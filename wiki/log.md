## [2026-08-22] bug | monitor.sh false "usage limit hit" auto-teardown fixed
Root-caused a repeated tmux-session crash/flap discovered during live Playwright-driven UAT verification (session died 3 times in one afternoon): `scripts/monitor.sh`'s poll loop initializes `all_idle=true`/`all_usage_hit=true` at the top of each tick, then for any agent whose pane is missing (`tmux has-session` fails), it only logged a WARN and `continue`d — never falsifying either flag. If *every* agent's pane happened to be absent on a given tick (e.g. immediately after a session (re)start, before windows finish spawning), both flags survived at their vacuous `true` default and the "all agents idle + usage limit hit → shut down" auto-teardown fired immediately, mislabeling a startup race as a usage-limit condition (confirmed unrelated to real Claude usage — `USAGE_CHECK_CMD='true'` in `conductor.conf` is a permissive placeholder that always reports "OK", rc=0, not "limited"). This produced a flapping restart→instant-teardown→restart cycle. Fixed by setting `all_idle=false`/`all_usage_hit=false` in the pane-not-found branch before its `continue`, so a fleet with any unobservable agent can no longer vacuously satisfy the shutdown condition — errs toward not tearing down when uncertain, rather than the previous fail-closed-to-shutdown behavior. `bash -n scripts/monitor.sh` clean; no shell-script test harness exists in this repo to add a regression test to.
