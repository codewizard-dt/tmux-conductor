# TASK-157 — Consolidate Terminal/Skills/Diff/Usage/Checkpoints into one tabbed panel in AgentDetailModal

implements::[[ADR-0005#D1]]

## Objective

Per `[[ADR-0005#D1]]` (reversing `ADR-0002#D1`'s no-go), replace `AgentDetailModal`'s current layout — an always-visible terminal (`LogTail`) above four independent stacked `<details>` accordions (Skills, `DiffPanel`, `UsageBreakdown`, `CheckpointList`) — with **one hand-built WAI-ARIA tabbed panel** holding five tabs, in order: **Terminal, Skills, Diff, Usage, Checkpoints**. Terminal is the default-active tab on modal open, preserving today's "terminal is what you see first" behavior. A tab whose panel would currently render `null`/not mount (Diff/Usage/Checkpoints, per-agent) is omitted from the tab strip entirely, not shown disabled.

**Why this is riskier than a typical accordion→tabs swap**: the terminal moving into a tab means it is only on-screen when its tab is active — this changes the modal's primary interaction model, not just its info panels. Two existing mechanisms assumed the terminal was always visible and must be updated so they still work correctly under tabs:
1. `TASK-131`'s "Direct Input default-on every `LogTail` mount" effect — must still fire/be visibly focused when the Terminal tab becomes active, not just on component mount (which under tabs may happen once, at modal-open, regardless of which tab is initially shown to the user if a future change ever makes Terminal non-default).
2. The needs-attention/notification-toast `armInteract`/`interactSignal` flow (`setExpandedAgent({ id, armInteract: true })`, `agent-detail-modal.md`) — opening the modal this way must also force the active tab to Terminal, or Direct Input auto-focuses a hidden, inactive panel the user can't see.

Re-locate all of the following via Serena (`find_symbol`/`get_symbols_overview`) before editing — `AgentDetailModal`'s body has had five concurrent tasks land on it this same day (TASK-148/150/152/153/154); do not trust any line number from prior research/task files.

1. [x] **Tab strip component** — new `frontend/src/components/AgentInfoTabs.tsx` (or inline in `AgentList.tsx` if a generic reusable component isn't warranted — decide based on whether `AgentActionsMenu.tsx`'s precedent of "one dedicated file per new interactive primitive" fits here too). Implement the W3C WAI-ARIA Authoring Practices **Tabs** pattern per `[[accessible-tabs-pattern]]`:
   - `role="tablist"` container of `role="tab"` buttons, `aria-selected`, `aria-controls` pointing at each `role="tabpanel"`'s id, `id` on each tab referenced by the panel's `aria-labelledby`.
   - Roving `tabindex` (`0` on the active tab, `-1` on the rest) with `ArrowLeft`/`ArrowRight` moving focus (wrapping), `Home`/`End` jumping to first/last *visible* tab (skip any tab omitted for absent content — there is no "disabled" tab state here, only present/absent).
   - Each `tabpanel` gets `tabindex="0"` so keyboard/AT users don't skip its content when tabbing through the page (per APG's documented safe default, `[[accessible-tabs-pattern]]`).
   - Tabs list is computed dynamically per-agent: Terminal always present; Skills always present (post-`TASK-153` flatten, still always renders even with zero skills — confirm current behavior via Serena and preserve it); Diff/Usage/Checkpoints present only when their existing mount conditions are true (mirror `DiffPanel`/`UsageBreakdown`'s current `return null` guards and `CheckpointList`'s worktree-only mount check exactly — do not change when these are considered "absent").
   - **Implementation note (step 1 done):** `AgentInfoTabs.tsx` created as its own dedicated component (matches `AgentActionsMenu.tsx` precedent). Full WAI-ARIA structure + roving tabindex + wrapping Arrow/Home/End implemented, keyed off `tabs.filter(t => t.present !== false)`. Panels are always mounted, visibility toggled via a `hidden` class (mirrors `LogTail.tsx`'s Live/History toggle exactly). **Key finding for step 2:** `AgentDetailModal` is not its own file — it and `UsageBreakdown` both live in `frontend/src/components/AgentList.tsx` (~lines 413, 562-1014). `DiffPanel`/`UsageBreakdown` compute "absent" via an **internal async data-driven** guard (`return null` only after their own fetch resolves) — this can't be read synchronously by a parent tab list. Step 2 will thread an `onPresenceChange(present: boolean)` callback into both so the tab list learns their presence without changing *when* they're considered absent (same condition, just relayed outward instead of self-contained). `CheckpointList` needs no such callback — its absence is already synchronous/external (`effectiveWorktreePath` truthiness).
2. [x] **Terminal-tab mounting** — the tab panel for Terminal wraps the existing `uses::[[log-tail]]` render call *unchanged*, but instead of unmounting when another tab is active, it must stay mounted and only be hidden (matching the existing precedent from the Live/History toggle inside `LogTail` itself, which keeps the underlying `Terminal`/xterm instance alive by toggling a `hidden` class rather than conditionally rendering — confirm the exact mechanism via Serena on `LogTail.tsx` before replicating it one level up). Do **not** let switching away from the Terminal tab and back dispose/recreate the `Terminal` instance, drop scrollback, or interrupt an in-flight Direct Input session — this is the single most important constraint in this task; get it wrong and every terminal-persistence guarantee `TASK-131`/`UAT-109` established breaks.
3. [x] **`armInteract`/`interactSignal` wiring** — when `AgentDetailModal` is opened with `armInteract: true` (needs-attention CTA, notification-toast click), force the tab state to Terminal on open (in addition to whatever `interactSignal` already does inside `LogTail`) so Direct Input's auto-focus lands on a visible panel, not a hidden inactive one.
4. [x] **`logExpanded` fullscreen (`⌥F`/double-click)** — this only makes sense while Terminal is the active tab (there is nothing to "expand" on Skills/Diff/Usage/Checkpoints). Decide and implement one of: (a) force-switch to Terminal when fullscreen is triggered from elsewhere, or (b) only expose the fullscreen trigger while Terminal is already active (simpler, avoids a surprising tab-switch side effect) — pick (b) unless a concrete UX reason surfaces during implementation to prefer (a).
   - **Implementation note:** Option (b) implemented as directed — `⌥F` keydown handler no-ops unless `activeTabId === 'terminal'`; `handleActiveTabChange` also collapses `logExpanded` when leaving the Terminal tab.
5. [x] Remove the four now-redundant standalone `<details>` blocks (Skills/DiffPanel/UsageBreakdown/CheckpointList) and the terminal's old always-visible position, replacing that whole region of `AgentDetailModal`'s body with the new tab strip + panels.
   - **Implementation notes (steps 2-5 done together, same integration pass):** `DiffPanel`/`UsageBreakdown` gained `onPresenceChange?: (present: boolean) => void`, reporting the exact negation of their original `return null` guards via `useEffect`; both default `present: true` at mount (deliberate — `present:false` fully unmounts the tab under `AgentInfoTabs`'s contract, so defaulting `false` would mean the component never mounts, never fetches, and can never report real presence — a permanently dead tab; cost is a possible one-frame tab flash). `CheckpointList` needs no callback — gated synchronously off `effectiveWorktreePath` same as before. `<details>` wrappers removed from `DiffPanel`/`CheckpointList`/`UsageBreakdown` (collapse no longer makes sense as a full tab panel). Terminal mounting persistence **confirmed**: `AgentInfoTabs` renders all visible tabs unconditionally each render (only `present:false` excludes one), `LogTail`'s `key={agent.id}` is unchanged and only remounts on agent-identity change (Prev/Next nav), never on tab switch; the `hidden`-class-only toggle means the xterm `Terminal` instance's creation effect (`[loaded, windowPresent, agentId]`) never re-runs from a tab switch.
   - **Known accepted limitation (not a terminal/Direct Input regression, so not escalated per Notes' bar):** because `present:false` fully unmounts a tab's content, if the Diff tab goes absent it stops listening for the `conductor:diff-refresh` window event; a checkpoint rollback that reintroduces a diff while the modal stays open on a different tab won't make the Diff tab reappear until the modal is closed/reopened. Narrow, self-correcting-on-reopen, and follows directly from this task's own spec'd "absent = omitted entirely" architecture (step 1) rather than being a defect in this integration pass — flagged here for UAT awareness, not blocking.
