## Scope note

TASK-157 replaced `AgentDetailModal`'s always-visible terminal (`LogTail`) + four stacked `<details>` accordions (Skills/Diff/Usage/Checkpoints) with one hand-built WAI-ARIA tabbed panel (`AgentInfoTabs`), five tabs in order Terminal/Skills/Diff/Usage/Checkpoints, Terminal default-active. This is flagged in the task as the highest-risk change `ROADMAP-021` has produced because it touches the modal's primary interaction model (terminal-first), not just secondary info panels — every case below targets one of the two mechanisms the task had to re-wire under tabs (Direct-Input default-on, `armInteract`/`interactSignal` auto-focus) or the terminal-persistence guarantee the tab strip must not break. `AgentInfoTabs.tsx` and the tab-switching mechanics already have thorough `vitest`/RTL coverage (`frontend/src/components/AgentInfoTabs.test.tsx`, and the `AgentDetailModal tabbed info panel (TASK-157)` block in `frontend/src/components/AgentList.test.tsx`) — those are cited as the repeatable-unit-test evidence for cases below where they apply; per the file's own comments, `LogTail` is mocked there because jsdom has no `window.matchMedia`, so a real `@xterm/xterm` `Terminal` cannot mount in that test environment at all. That gap is exactly why the real-browser cases below exist.

Only TASK-157's own behavior is exercised here — pre-existing Skills-tab content (`TASK-153`), the header identity pill (`TASK-152`), and color tokens (`TASK-150`) are out of scope.

- [ ] `make dev` running from the repo root — host-server on `:8788`, frontend dev server on `:4321` — dashboard reachable at `http://localhost:4321`

### UAT-UI-003: Terminal (xterm) instance persists across tab switches in a real browser
- **Page**: `http://localhost:4321` (agent board)

Unit coverage for this mocks `LogTail` (jsdom can't mount real xterm — no `window.matchMedia`), so this is the real-browser check that closes that gap.
- **Steps**:
  1. Open `AgentDetailModal` for an agent with a live window and enough terminal output to scroll (or generate some by dispatching a task/command).
  2. In the Terminal tab, scroll the live terminal view up so it's **not** pinned to the bottom.
  3. In the browser console, tag the rendered terminal DOM node so identity can be checked later, e.g.: `document.querySelector('[role="tabpanel"][aria-labelledby$="-tab-terminal"] .xterm')?.setAttribute('data-uat-marker', '1')`.

Scroll position is preserved exactly across switches — no reset-to-bottom flash. ### UAT-EDGE-002: Known accepted limitation — a diff reappearing via checkpoint rollback doesn't re-show the Diff tab until the modal is reopened
- **Scenario**: Documented in the task's Approach (step 5) as an accepted, non-blocking limitation, not a defect: because `present: false` fully unmounts a tab's content, an absent Diff tab's `DiffPanel` isn't mounted and therefore isn't listening for the `conductor:diff-refresh` window event `CheckpointList` dispatches after a rollback. If a checkpoint rollback reintroduces a diff while the modal is open on a different tab, the Diff tab will not reappear until the modal is closed and reopened.
- **Steps**:
  1. Use the worktree agent from the prerequisites. Ensure its working tree currently has **no** diff (commit or discard any pending changes) so the Diff tab is absent, and that it has at least one earlier checkpoint recorded from when it *did* have a diff.
  2. Open the detail modal — confirm the Diff tab is absent from the strip (Checkpoints tab still present).
  3. Switch to the Checkpoints tab and roll back to the earlier checkpoint that reintroduces a diff (confirm the "Roll back to this checkpoint?" dialog, confirm label "Roll back").
  4. Without closing the modal, check the tab strip.
  5. Close the modal and reopen it for the same agent.
- **Expected Result**: Step 4: the Diff tab does **not** reappear in the strip even though the working tree now has a diff again — this is the accepted limitation, expected behavior, and should **not** be recorded as a failure. Step 5: after reopening, the Diff tab is present again (fresh mount cycle picks up the real state). Flag any deviation from this exact behavior (e.g. the Diff tab reappearing live without reopening, which would be a pleasant surprise but contradicts the task's documented mechanism — mention it rather than failing the case; or the Diff tab *never* reappearing even after reopening, which would be a genuine regression and should fail).
