# Wiki Index — Home Map

The page catalog and home Map of Content for this wiki. **Read this first on every query**, then drill into the linked pages. Updated on every ingest and every filed answer.

Conventions that govern every page (atomic pages, stable IDs, typed links, frontmatter namespace): see [conventions](conventions.md). Operation history: see [log](log.md).

Entry format: `- [Title](path) — one-line summary`.

The wiki is split into two domains with opposite organizing laws:
- **Knowledge** — timeless, link-navigated synthesis (sources, concepts, entities). Pages are listed individually below.
- **Work** — stateful, status-navigated lifecycle artifacts (requirements, decisions, roadmaps, tasks, uat, bugs). Items are **not** listed here — each family keeps its own `index.md` of active items; this page links to those.

- [LLM Orchestrator Runtime Options (tmux Agent vs. claude -p vs. Agent SDK)](knowledge/concepts/llm-orchestrator-runtime-options.md) — host-server has no Claude runtime; `claude -p` subprocess recommended as the first LLM step (enqueue-only, turn-capped); SDK if billing/auth is clarified; orchestrator-as-tmux-agent has the widest blast radius
- [Listing a Repo's Files from the Git Index](knowledge/concepts/git-index-file-listing.md) — `git ls-files -co --exclude-standard` honors every ignore file for free and is ~50× cheaper than a walk on big dep dirs; caveats: deleted-but-indexed files, no empty directories, non-git fallback needs caps
- [React File-Tree Component Options](knowledge/concepts/file-tree-ui-library-options.md) — Headless Tree (recommended), react-arborist (fallback), @pierre/trees (beta, path-first), or hand-rolled; virtualization unnecessary at ~900 paths, keyboard/ARIA work is the real cost
- [Localhost Server with CORS `*`](knowledge/concepts/local-server-cors-wildcard-exposure.md) — loopback bind doesn't stop cross-origin reads from any page in the user's browser; blocks serving file contents until `CORS_ORIGIN` is restricted and paths are realpath-jailed
- [Agent Role as Capability Grant, Not Permission Wall (No-Auth Trust Model)](knowledge/concepts/agent-role-capability-grant.md) — with no auth, a headerless call is "human", so a role can't deny anyone; it can grant a route set, constrain recognised callers (no self-target, no orchestrator-creates-orchestrator, fleet cap, confirm on delete) and attribute actions; identify callers by numeric agent id, not the non-injective window name
- [Evaluating a Heuristic State Detector (Three-Tier Testing)](knowledge/concepts/state-detector-evaluation-tiers.md) — branch tests (0-switch) → golden fixtures grown from real incidents (characterization testing) → production log + offline analysis is a reusable pattern for any heuristic classifier; missing 1-switch sequence tests and a human-calibrated false-positive baseline are the next increments
